# Changelog

All notable changes to Fileflux are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project intends to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) once it has a first release. The crate is currently at `0.1.0-dev.0`; nothing has been released yet.

## [Unreleased]

### Added

- The nightly tarball now ships `bin/fileflux-owner-helper` and both polkit policies (`packaging/`), so the prebuilt package gets the safe owner change and the `dev.fileflux.open-as-admin` action instead of the `pkexec chown` and `pkexec env` fallbacks. `nix/binary.nix` installs them per channel (`libexec/nightly/fileflux-owner-helper`, `dev.fileflux.owner-helper-nightly.policy`, `dev.fileflux.open-as-admin-nightly.policy`, action ids with a `-nightly` suffix) so `fileflux` and `fileflux-nightly` install together; a launcher named `fileflux-<channel>` looks for its own helper and policy file.
- Disk usage analyzer: after a cleanup the status line sets the estimated freed space beside the volume's real free space (`statvfs`, the sidebar meter's source, read off the UI thread) and how it changed since the analysis; a folder on a gvfs mount (phone, network share) is no longer walked without asking, like the details panel's size (**Measure anyway**); and the chart gains keyboard navigation (arrows move a visible cursor between slices and rings, Enter drills down, Backspace or Escape goes up), a selectable "Other" slice that highlights the folded items in the list, and a ring zoom (Ctrl+`=` / Ctrl+`-` or the wheel, one to six rings). The three rows leave the roadmap's analyzer table.
- The mouse's back and forward side buttons walk a pane's history (also in a disk usage analysis), like Alt+← and Alt+→; in a split they act on the pane under the pointer. Only the image viewer handled them before.
- `scripts/install-desktop.sh --default-folders` makes Fileflux the default application for folders (`inode/directory`); `--uninstall` restores the previous default. The desktop entry already declared folders, but the script only ever set the image types.
- Opening a program asks first. Double click, Enter or Open on one file that you may execute and that starts with the ELF magic or `#!` shows **Run**, **Run in Terminal**, **Open** and **Cancel** (Cancel is the default, so Enter never runs it). Run starts it detached in its folder with no shell, Run in Terminal uses the terminal Fileflux already finds for Open in terminal, and Open is the default application as before. Files with the execute bit that are not programs (everything on vfat, ntfs or MTP) and several selected files open as they did. A `.desktop` file now opens in the default `text/plain` application (Open with… when none is set) instead of `xdg-open`, which could launch it, and its context menu gains **Launch**, which runs its `Exec=` line with no files (in the terminal for `Terminal=true`).
- Rename and reorder the sidebar's favorites. Right-click a row of the Favorites section for **Rename…** (writes the GTK bookmark's label; an empty name shows the folder's name again), **Move up** and **Move down**, or drag a favorite to the top or bottom edge of another favorite row: an insertion line shows where it lands and the drop reorders. Dropping on the middle of a row or on the entries area keeps working as before. Only the changed line of `~/.config/gtk-3.0/bookmarks` is rewritten (comments, network bookmarks, other labels, order and line endings are kept), atomically like add and remove, so Nautilus and Thunar see the same names and order.
- **Open as Administrator**: a context-menu row on one folder and on a folder's empty space starts a separate Fileflux window as root through `pkexec` (polkit's own dialog; no password is seen or stored), with the new action `dev.fileflux.open-as-admin` (`packaging/dev.fileflux.open-as-admin.policy`, installed by the Nix packages) or, without it, `pkexec env DISPLAY=… XAUTHORITY=…`. The root instance never forwards to or claims your single-instance D-Bus name (new `--new-instance` flag; also implied for uid 0) and shows a fixed red banner "Running as administrator — changes affect the whole system" and " (root)" in its window titles. The row is hidden for root and refused for the Trash, Recent, search and phone, network or FUSE mounts.
- Video thumbnails out of the box with Nix: the `fileflux-source` and nightly packages and the dev shell bring `ffmpegthumbnailer` and append its thumbnailers to `XDG_DATA_DIRS` (after the system's, which keep priority), so videos get a preview without installing anything else.
- Copy and paste files with other file managers: Copy and Cut put the files on the system clipboard as `x-special/gnome-copied-files` and `text/uri-list` (plus KDE's cut flag for a cut), so Nautilus, Thunar or Dolphin paste them; Paste takes files those applications copied or cut, and a cut moves them through the usual conflict dialog, progress and Undo. Pasting `file://` URIs or absolute paths as text still works, and a clipboard Fileflux owns behaves as before. Needs DBFlux `85ce001` (dbflux#1384).
- Icons from the installed freedesktop icon theme: a file shows the icon of the application that handles it — Blender's for `.blend`, the script icon for a shell script, the document icon for a PDF — taken from the theme the desktop is configured to use (`gtk-3.0/settings.ini`, its `Inherits=` chain, then `Adwaita`, `breeze`, `Papirus` and `hicolor`), remembered per file type so nothing probes per tile. Types the theme does not name keep the extension-derived glyph.
- Previews for what the app cannot decode itself: videos, PDFs, office documents and vector images get a thumbnail in the grid and the details panel from the freedesktop thumbnailers installed on the system (`~/.local/share/thumbnailers` and every `$XDG_DATA_DIRS/*/thumbnailers`), the same commands pcmanfm, Nautilus and Thunar use — `ffmpegthumbnailer` or `totem-video-thumbnailer` for video, `evince`'s or poppler's for PDF. Each one runs without a shell, is killed after 10 s, and its output is decoded and rewritten into `~/.cache/thumbnails` as the standard requires, so the other file managers reuse it. With no thumbnailer installed for a type, the tile keeps its kind glyph.
- The status bar names the selected file's type when exactly one entry is selected: `1 selected · Document · PDF · 56.3 KB`, using the same label the details panel shows.

### Changed

- The run prompt arms **Run**, **Run in Terminal** and **Open** like a danger button (about 0.4 s after it appears), so a stray trailing click never runs a program. **Run in Terminal** and `Terminal=true` launchers no longer let the terminal re-parse the program path: konsole, xterm and unknown terminals get the program through `/bin/sh -c 'exec "$@"'` (a lone `-e <arg>` is re-split by them), the others take their own argv-preserving form, and a terminal found through a desktop entry honours its `X-TerminalArgExec`. Opening a file that may be a program probes it once per path and gives up after 1.5 s (a hung mount), opening it as before. Dragging a folder from the entries area onto a favorite row's edge no longer reorders the favorites; only a drag that began on a favorite row does.
- Entering a folder with thousands of images and videos no longer keeps the window busy while the previews fill in. The thumbnails of a listing are made by a few workers (half the cores, two to four) that take the tiles on screen first and follow the scroll; what arrived is shown together every 150 ms and the window is redrawn only when a visible tile (or the selected file's preview) got a thumbnail, where before it was redrawn for every batch of 32 lookups and every generated thumbnail. In the sandbox with 800 JPGs, 200 PNGs and 120 videos that is about half the frames while the thumbnails stream in, and the UI thread waits for its timers a third as long. Leaving the folder stops the pending work.
- The details panel previews an image over 1 MiB by its 256 px thumbnail instead of decoding the whole photograph (stepping through 47 JPGs of 3000×2000 took the process from 355 MB to 1.9 GB; it now stays near 530 MB). Smaller images are still shown whole.
- Thumbnail work is more robust: a big image's details preview no longer falls back to its icon once the folder's smaller thumbnails arrive (a smaller thumbnail never replaces a larger one for the same unchanged file, and the preview is asked again when the file changes); a decoder that panics leaves its tile with the icon instead of keeping the window's 150 ms refresh running forever; the two-to-four worker limit is now shared by every tab and pane (the tab on screen keeps a permit), so several media tabs cannot occupy all the background threads; changing the filter, hidden files or sort re-orders the pending thumbnails for what is now on screen, and a new folder starts from its top.
- The icon theme's icon for a file type is looked up, and the icon rasterized, on a background thread; a tile shows its bundled glyph until the answer arrives, so no frame probes the filesystem.
- Failed operations say why and for which item, in plain words, instead of a bare "Could not …" or the system's raw text ("Permission denied (os error 13)"): "Could not move “a.txt” to Documents: you don't have permission to do that". Several failures are summarized by reason in the toast ("…: you don't have permission to do that (2), there is no space left on the device (1)") and **Details** keeps one line per item. Create, rename, copy, move, links, Compress/Extract, templates, Trash (move, restore, delete, empty), permissions and Undo follow the same wording; no notice shows "os error" any more.
- The Nix source build (`nix build .#fileflux-source`) works again: the DBFlux pin moves to `85ce001`, whose patched GPUI crates are no longer inside its workspace (dbflux#1383), so Nix can vendor them.
- Themed file icons now draw in full colour instead of one flat silhouette. GPUI's SVG element paints an alpha mask, so the first theme-icon pass rendered every themed icon as one grey shape; Fileflux now rasterizes the theme's SVG and PNG icons itself, at the size it draws them, and rasterizes each (icon, size) once per session. Common text the theme does not name per type — logs, lock files, INI-style config, `.gitignore` and friends — now resolves to the plain-text icon.
- A grid tile is its entry everywhere inside it: clicking the padding around a tile's icon or name now selects it, where before only the drawn icon and name did, and the hover wash and the click area are the same rectangle. The rubber band therefore starts only from real empty space — the gaps between tiles and rows, the margins, and the area right of the last column and below the last row — instead of from a tile's blank corners.
- Dragging entries now needs the pointer to move 8 px from the press (the desktop's drag threshold, GPUI's own is 2 px). Before that the drag is inert: no preview, no drop-target highlight, no drop and no selection change, and releasing there acts as the click it was, so a slight slip while clicking can no longer move a file. The rubber band uses the same threshold to tell a drag from a click on empty space.

### Added

- Rubber-band selection: drag on the empty space of the folder pane, in the grid or the list and in both panes, to select the entries a rectangle covers, live. Ctrl toggles and Shift adds against the selection from before the drag, the pane scrolls while the pointer rests near or beyond the top or bottom edge, Escape cancels and restores the earlier selection, and a plain click on empty space still clears the selection. The band starts from any empty point of the pane, including the margins and the blank part of a tile around its icon and name; only the drawn icon, name or list row is the entry. A click on empty space is no longer ignored when an earlier drag left GPUI's drag state behind. Hit testing is layout arithmetic, so it stays fast on huge folders.
- Drag files out to other applications: dragging the selection past the window's edge hands it to the desktop as a file list (`text/uri-list`), so it can be dropped on a browser, chat or another file manager. Wayland only for now; on X11 the drag stays inside Fileflux.
- Cascading submenus in context menus, on Bolt's cascade (DBFlux `7ceb70b`): the empty-space menu's **Sort by** and **Filter** open beside the menu instead of replacing it, with hover (after 150 ms), →/Enter, ←/Escape, a flip to the left at the window's right edge, and live check marks that keep the menu open. The subbar Sort and Filter buttons open the same options. The drill-in pages and their "Back" rows are gone.
- Dual pane: F3 or the toolbar's Split view button shows two folders side by side. Each pane has its own tabs, location, history, view, sort, filters and selection; the focused pane has a tinted top edge and the sidebar, breadcrumbs, path field, search and keyboard act on it. F6 switches panes, and clicking a pane focuses it. F5 copies and Shift+F5 moves the selection to the folder the other pane shows, through the same paste engine as Ctrl+V (conflict dialog, progress card, Undo), and refuses with a toast into the Trash, Recent and search results. Drag and drop works between panes, live refresh covers both, and the session remembers the split and both panes' tabs (a `session.toml` without them loads as one pane). The split needs a window at least 1100 px wide; a narrower window shows one pane at a time, and the details panel is not drawn while split.
- Missing image thumbnails are generated into the freedesktop cache (256 px, EXIF-upright, two at a time).
- Open with: Other application with a filter, and Remember for <type> writing mimeapps.list.

- Search in subfolders: a toggle by the search box and Ctrl+Shift+F search file names in the folder and everything under it. Results stream into a read-only view that shows each match's folder; the walk is breadth-first, off the UI thread, cancellable with Escape, never follows symlinked folders, stays on one filesystem, follows the hidden-files rule, and stops at 10,000 matches ("N found · searching…", "stopped at 10,000"). Enter, Open containing folder and the file operations work on results. A search tab is not saved in the session.
- Recent view in Places from the freedesktop `recently-used.xbel` (read-only, live, Open containing folder, restorable tab).
- Grid thumbnails reuse current entries from the freedesktop thumbnail cache.

- Native Bolt file explorer on GPUI: places sidebar, breadcrumb path bar with an editable field, back/forward/up history, grid and list views, folder subbar, status bar with free space, and a dark theme.
- Command line: open a folder or file's parent, open images in the viewer, `--help` and `--version`, clear errors with exit status 2 for missing paths.
- Image viewer in a window of its own: folder browsing, zoom, pan, rotation, info panel, fullscreen, animated GIF and WebP, and `scripts/install-desktop.sh` to register Fileflux as an image handler.
- Open images from the explorer in the viewer, in the explorer's sort and filter order.
- Details panel with an image preview, kind, size, modified time and permissions.
- Live refresh of every tab's folder through one shared inotify watcher thread.
- Tabs with per-tab location, history, selection, view, sort and filter; background tabs stay current; open in new tab by middle click or from menus.
- Sort (name, size, modified, type, natural order, folders first) and filters (type, hidden files, modified, size, name search), in the subbar and the context menu.
- File operations: new folder and file, inline rename, Move to Trash and restore with Undo, permanent delete behind a confirmation, Empty Trash, Copy path, Open with…, Open in terminal, Properties.
- Copy, cut and paste with byte-based progress, cancel, and a conflict dialog (Skip, Keep both, Replace); drag and drop to move, copy or trash.
- Identity-checked undo for rename, trash, create, copy and move.
- Context menus that name their target, a sidebar menu, and resizable sidebar and details panel.
- Settings and session persistence: preferences and open tabs saved atomically to `settings.toml` and `session.toml`, tolerant of broken files, symlinks and several instances.
- Devices: mount, unmount and eject from the sidebar through `udisksctl`, with busy and draining guards.
- Favorites are your GTK bookmarks (`~/.config/gtk-3.0/bookmarks`), shared with Nautilus and Thunar: edits are atomic, keep every other line, label and comment, and show live in the sidebar. Favorites an older `settings.toml` held are moved there once.
- Hidden files follow the `.hidden` file convention (names listed one per line, as in Nautilus and Thunar) as well as dotfiles.
- Open in terminal on a folder, a sidebar row and the empty space, resolved like xdg-terminal-exec (`$TERMINAL`, `xdg-terminal-exec`, `xdg-terminals.list`, desktop entries, known terminals), with no shell.
- Phones (MTP), network shares and other gvfs mounts are listed under Devices with friendly names, and the device list refreshes from events (inotify and mount table) instead of polling.
- Continuous integration (fmt, clippy, tests, release build), a nightly workflow that publishes a prebuilt binary to a rolling `nightly` release, and flake packages (`fileflux`, `fileflux-source`, `fileflux-nightly`), apps and an overlay.
- Apache-2.0 license, user documentation under `docs/`, `CONTRIBUTING.md`, and issue and pull request templates.

### Changed

- The narrow-window sidebar overlay now spans the area above the status bar like the docked sidebar, instead of ending short with a clipped bottom row and a corner artifact.
- Folders are sorted by Modified, newest first, and hidden files are hidden by default (Ctrl+H shows them, with a "Hidden shown" chip). Settings and session files move to `version = 2`: a saved *Name, ascending* sort and `hide_hidden = false` (the old defaults) are migrated, any other saved choice is kept.
- Toasts stack in the bottom-right corner and close sooner: 3 s for info and success, 6 s with Undo, 8 s for errors and warnings, at most 3 at once.
- The explorer started as a read-only browser and now supports file operations built on safety defaults: Trash first, no silent overwrite, partial-then-rename copies.
- Image thumbnails, two-tone folders and a full-width details table replace the first plain listing.
- The viewer rotates decoded pixels with the `image` crate.
- Devices lists mounted volumes, one entry per device, and unmounted removable filesystems.
- CI runs with read-only permissions; the nightly build waits for CI to succeed on the exact commit, builds with `--locked`, publishes before pruning, and keeps the 14 newest per-build assets by upload time. Third-party actions are pinned by commit.

### Fixed

- The mouse back and forward buttons now give the pane they were pressed in the focus before moving its history, instead of relying on an earlier press handler; a sidebar press that nothing released (for example in a disk usage view) no longer stays pending for a later click.
- Failed or stale submits in the path field no longer change the committed folder, and the fields stay in sync after navigation.
- Command-line paths containing `..` are folded, and the current directory is needed only for relative paths.
- File operation dialogs and undo hardened against stale or background results.
- Temporary transfer files are hidden from folder listings.
- "Open with…" refuses `Exec=` entries that quote a field code, so a file name cannot run as a shell command.
- Navigation wins over the refresh of a finished operation, and affected folders are de-duplicated.
- Watched folders are identified by their kernel watch descriptor; replaced folders are re-watched and lost watch removals recovered.
- Settings saves hardened against crashes, concurrent instances and symlinked files.
- Operations on a device being ejected are blocked, and symlinks are resolved in device checks.
- The Empty Trash action empties only the items the confirmation counted.
- Listing a folder never blocks on a FIFO or device node named `.hidden`.
- Every navigation is gated while a device is being ejected, and refused undos stay available during an eject.
- Bookmark edits made by other programs are kept when Fileflux writes the file, the favorites migration finishes cleanly, and relative legacy favorites are skipped.
- Only an invalid saved sort is reset on load, not a valid one.
- Copies on FUSE filesystems (gvfs, sshfs) tolerate `EINVAL` from the no-replace rename, and a direct copy is cleaned up by file identity if it fails or is cancelled.

### Performance

- Directory listings are indexed once and sort and filter results are cached.
- Large folders are arranged on the background executor, so typing and clicking stay responsive on very large folders.
- Folder item counts and permissions are read off the UI thread.
